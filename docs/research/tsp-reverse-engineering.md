## 4. 五大机制精拆(逆向的核心产出)

### 4.1 能力路由矩阵 ★最精华
- 6 类数据集(日K/复权因子/实时行情/分钟K/财务/五档)**按源声明的能力独立路由**:
  "换源不换口径"——指标计算与回测口径不变,只换底层数据源。
- **fail-closed**:数据源未声明 `pct_unit`(复权口径单位)即拒绝接入——宁可不路由,
  不静默错算。这与萤火"缺口不静默造分"同一条纪律的数据源版。
- 现役源:TickFlow(官方 SDK,档位探测 None/Free/Starter/Pro/Expert)、fuyao(同花顺
  REST)、TdxQuant(通达信);YAML 自定义源 + ZIP 插件安装。
- **萤火痛点直击**:11-16 事故的根因=EM 单点绑定(EM 挂→日更瘫痪,两天无快照)。
  TSP 的能力路由就是这类事故的**架构级免疫**:每个能力可独立切源,口径不变。

### 4.2 Enriched Parquet 一次扫表
- 只存 15 列基础数据,现算 68 列指标信号,**一次扫表落盘 enriched Parquet**;
  策略→回测→监控→复盘共享同一口径。
- 萤火对应:factor_panel(161 万行)同思路;TSP 把"口径共享"从约定升级为
  **存储结构**——同表即同口径,跨页无法口径漂移(我们 11-17 宽度史停更事故的
  反面教材:同名字段两处维护=口径漂移温床)。

### 4.3 回测稳健筛选(防过拟合的三件套)
- K 段折外稳健分:**0.6×中位 + 0.4×最差**(不是均值!中位抗离群,最差防幸存)。
- Top-20 退化率(参数寻优后样本外退化幅度)。
- 滚动样本外检验 + 最小交易数门槛。
- 策略守护:每日 K 段复验→自动判定**健康/观察/退役**;健康冠军低相关
  (日收益 Pearson≤0.7)才可组合。
- 萤火对照:walk-forward(purge+embargo)已有,但"退化率/稳健分/策略退役制"是
  **上线后生命周期管理**,萤火缺这块(注册表管结论,不管策略的持续健康)。

### 4.4 MCP + 契约端点(scope 化开放)
- Token SHA-256 存储 + 六档 scope(read:market/read:ext/write:ext/read:analysis/
  run:backtest/paper:trade) + 65 端点契约 + 120 次/分限流 + SSE 事件流。
- **MCP server:模拟盘交易刻意不对 AI 开放**——AI 只读市场/分析,动钱必须人。
- 萤火对应:方法论 #10"半自动是个人开发者的正确形态:agent 提案+人过审,审计不能
  外包"——**同一条纪律的两个工程形态**。萤火可开 read-only MCP 让 AI 助手查湖
  (信息层能力扩展),write scope 永不下放。

### 4.5 内存治理(单机生产化的暗功夫)
- `POLARS_MAX_THREADS=2`、worker RSS 上限 6GiB、重任务内存闸 1GiB、DuckDB 并发 3、
  mem_limit 1500m——2GB 机器可跑。
- 萤火对照:终极回测 1.6M 行训练多次吃内存告警,TSP 的"内存闸+上限"是单机生产化
  的必答题,值得抄参数。

## 5. 萤火 × TSP 对账表

| 维度 | TSP(工具) | 萤火(制度) |
|---|---|---|
| 数据源 | **能力路由矩阵,换源不换口径,fail-closed** ← 强 | 单点绑定(EM 主源),事故已证痛点 ← 弱 |
| 数据治理 | 15 列基础+68 列现算,enriched Parquet | PIT 版本化湖+双源对账+退市回补 ← 强 |
| 回测 | T+1 引擎+稳健三件套+策略守护 ← 强 | walk-forward+非重叠调仓+配对差,无退役制 |
| 研究治理 | 无(工具不管结论) | **注册表+反方陈述+DSR+理论溯源** ← 强 |
| 统计审计 | 无独立审计层 | NW/bootstrap/事件研究置换 ← 强 |
| 开放性 | 65 契约端点+MCP+scope ← 强 | CLI+bat,无 MCP ← 弱 |
| 界面 | React 19 页面工作台 | 静态 HTML 看板 ← 弱(够用) |
| 测试 | 3000+ 全绿+契约快照 | 176 全绿,缺契约快照 ← 待补 |
| 结论文化 | 无 | 负面结论入册+理论溯源 ← 强 |

**一句话**:TSP 是"个人量化的基础设施天花板"(工具层),萤火是"个人量化的研究
制度层"(结论层)。两者几乎不重叠——所以互为补集,**不是竞品,是上下楼**。

## 6. 吸收清单(按优先级,全部预注册)

1. **能力路由矩阵**([P-REA-1],架构级):collect 层重构——每类数据(日K/分钟/实时/
   财务/复权)声明能力,EM/新浪/TDX/东财按能力注册,主源挂自动降级备源,
   未声明口径的数据源拒绝接入(fail-closed)。直接免疫 11-16 类事故。
2. **端点契约快照测试**([P-REA-2]):四能力对账待补的"黄金 fixture"具体形态——
   CLI 输出/JSON schema 快照进测试,口径变更必须显式更新快照。
3. **策略守护机制**([P-REA-3]):注册表结论对应的策略加"健康/观察/退役"三态,
   日报风控面输出;复用 [S7] 分年 IC 作健康指标。
4. **MCP read-only server**([P-REA-4],远期):AI 助手查湖(Read scope only),
   write 永不下放。
5. **稳健分公式**(参考):K 段折外 0.6×中位+0.4×最差——[S7] 系列验证协议增补候选。

## 7. 不吸收清单(理由)

- React 工作台前端:萤火纪律="静态 HTML 零依赖看板够用",界面复杂度≠研究能力
  (工具光鲜≠结论可信——徒有其表判据的正面应用)。
- LLM 驱动策略定制:萤火纪律="agent 提案+人过审"(#10),LLM 直接写策略+扫全 A 股
  =DSR 灾难(试验数不可控)。
- vectorbt 双路径:回测引擎唯一执行路径(单一 StrategyEngine.run)反而是对的;
  萤火维持自有口径,不引第二回测引擎。

## 8. 逆向结论

TSP 用开源的方式实现了"同花顺该有但没有的工程化"——它的能力路由、契约端点、
稳健筛选三件套是行业级设计。**但对萤火,它最大的价值不是"替代谁",而是把
萤火最大的架构债(数据源单点绑定)给出了标准解法**。萤火相对 TSP 不可替代的部分
恰恰是 TSP 没有的:研究结论的治理制度。工具可以借,结论必须自己审判。
